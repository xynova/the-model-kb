# Model roster

Decision shelf for choosing a model for a task: price, third-party capability signals, and your own experience notes. Not a news archive.

Long-term destination: [OBJECTIVE.md](OBJECTIVE.md) (fit, cost, host limits, and a path to scored routing).

Differs from [library/](../library/): library is "interesting to revisit later"; roster is "open this when picking a model now." The same model may appear in both; roster does not auto-create library entries.

## Kind first

Every card has a required `kind`. Sovereignty means **portable open weights**, not who owns today's GPUs.

| Kind | Meaning |
|------|---------|
| `sovereign` | Open / self-hostable weights you can move between hosts (local, Cloud Run, Cloudflare-hosted open models, DeepInfra-hosted open models) |
| `provider` | Lab-locked API (OpenAI, Anthropic, Gemini, …). A host is `provider` only when it **proxies** that locked API |
| `service` | Model supplied inside a product (e.g. Cursor) |

Cloudflare can host open models (`sovereign` + `runtime: cloudflare`) or proxy Claude/OpenAI/Gemini (`provider`). Never infer `kind` from the host name alone.

## How to browse

- Scan [INDEX.md](INDEX.md) for name, kind, category, status, and tags.
- Filter with ripgrep on frontmatter, for example:

```bash
rg -l 'kind: sovereign' roster/
rg -l 'status: reach-for' roster/
rg -l 'runtime: cloudflare' roster/
rg '^name: ' roster/**/*.md
```

## How to add or refresh

1. Prefer the project skill `model-roster` (add with one-candidate `y`/`n` keep gate; refresh stale prices/signals; INDEX refresh).
2. Manual: copy [_template.md](_template.md), place under the right category, fill fields from [taxonomy.md](taxonomy.md), then run:

```bash
make -C site generate-roster
make -C dbt build
```

The second step writes [scores.json](scores.json) for agents and `tools/roster-pick`.

## Nightly host mine

GitHub Actions workflow `roster-mine` (cron 16:00 UTC) runs `make -C site mine-hosts`, then `make -C dbt build`, and opens or updates PR head **`roster-mine`** when there is a diff. It never pushes `main`.

Pipeline: `generate-roster` → `retrieve-limits.py` (public pages) → `apply-mine.py` → `generate-roster`. Review rows land in [retrieval/limits-review.json](retrieval/limits-review.json). **`capacity` on cards changes only** when you add a row to [retrieval/capacity-decisions.yaml](retrieval/capacity-decisions.yaml) (`name`, `host_id`, `capacity`); page suggestions do not auto-apply.

Local dry run: `make -C site mine-hosts` (network for retrieve).

## Polypus catalog diff

`make -C site polypus-diff` GETs `$POLYPUS_BASE_URL/v1/apis/openai/models` (default `http://127.0.0.1:1320`) and prints which gateway ids already match `catalog.json` `runtime_model_id` values, which look like new **model-roster** keep/drop candidates, and which are embeddings/audio/router skips. It does not write cards, mint a `polypus` host, or file prices. Use `--url` for a full models URL, `--json` for the report object. Tests inject a payload; they do not hit the network.

## Providers mint

New serving companies (for example Xinference) are **not** discovered by the nightly spider. Use project skill `providers-mint`: name a host or paste a public pricing URL, wait for `keep? y/n`, then the skill updates [taxonomy.md](taxonomy.md), `ALLOWED_HOST_IDS`, and retrieve-limits `LINK_KEYS`. Perplexity may suggest a name; filed URLs and prices MUST come from that public page. Attaching the host to a model card is `model-roster`, after the id exists.

## Keep rule

Keep only if you would open this card when choosing a model for a real job. Drop spectacle, one-off demos, and cards with no named use.
