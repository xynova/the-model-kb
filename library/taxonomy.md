# Library taxonomy

Source of truth for categories, tags, and keep criteria. The `ai-library-intake` skill MUST Read this file before assigning `category` or `tags`.

## Keep criteria

Keep an item only if you can name a future job for it:

- Run it locally
- Wire it into a pipeline
- Compare it when choosing a model or tool

Drop news, spectacle, closed APIs you will not pay for, and research with no attached job.

## Categories (exactly one per entry)

| Category | Use for |
|----------|---------|
| `models` | LLMs and multimodal foundation models |
| `video` | Video generation, extension, transcription tied to video |
| `3d` | Text-to-3D, scene reconstruction, 3D cleanup |
| `agents-memory` | Agent memory, voice memory, long-context agent systems |
| `robotics` | Robot models, demos, humanoid systems |
| `hardware` | Local AI boxes, chips, offline personal AI devices |
| `training-research` | Training methods, benchmarks, research techniques |
| `creative` | Agentic creative workspaces, image gen/edit products |

Directory path: `library/<category>/<slug>.md`.

## Indexes

- `library/INDEX.md` — global skim table (all entries). Columns: name, title, category, **summary**, **tags**, **run**, **license**. Regenerated by `library-intake index refresh`.
- `library/<category>/INDEX.md` — per-section skim table (same columns without category). Same refresh command.
- `library/additions/INDEX.md` — index of ISO weeks (`YYYY-Www`) with human date ranges.
- `library/additions/YYYY-Www.md` — one week of keepers, titled with the calendar span (for example `Sep 14–20, 2026`). Open/closed status is derived from each entry's `added` ISO week vs the current week (no manual close).

Hugo ignores `INDEX.md` authoring files and mounts week files under `/library/additions/`. Category section pages on the site render an Index from entry frontmatter (`summary`, tags, run, license).

Skim surface: **summary** (one-line what it is), **tags** (labels), **run**, **license**. Keep `does`, `status`, and `added` on the entry for filing, filters, and weekly grouping; they are not INDEX columns.

## Allowed tags

Tags are lowercase kebab-case labels shown on INDEX rows. Use only values from this list unless the user explicitly adds a new tag to this file first.

### Modality

- `llm`
- `vision`

- `3d`

- `audio`

## Status values

Exactly one of:

| Status | Meaning |
|--------|---------|
| `watch` | Interesting; revisit when a need appears |
| `reach-for` | Prefer this when the job matches |
| `drop-until-needed` | Noted; do not invest until a concrete job exists |

## Frontmatter fields

| Field | Required | Notes |
|-------|----------|-------|
| `name` | yes | Stable slug id (kebab-case), unique across the library |
| `title` | yes | Human display name |
| `summary` | yes | One-line what-it-is for INDEX skim (first sentence of **What it is**) |
| `category` | yes | One of the category keys above |
| `does` | yes | Exactly one value from the Does table (filing label, not an INDEX column) |
| `tags` | yes | List from the allowed set (INDEX labels) |
| `status` | yes | `watch` / `reach-for` / `drop-until-needed` |
| `run` | yes | `local` / `api` / `hardware` (INDEX skim) |
| `license` | yes | `open` / `closed` / `mixed` (INDEX skim) |
| `vram_hint` | no | Short hint, e.g. `consumer`, `multi-gpu`, `unknown` |
| `links` | no | Map: `homepage`, `github`, `weights` (omit missing keys) |
| `media` | no | Map: `cover` (repo-relative path to primary still), `gallery` (list of repo-relative still paths). Paths live under `library/<category>/<slug>/media/` |
| `source` | yes | Where the candidate came from |
| `added` | yes | ISO date `YYYY-MM-DD` |

Uncertain enrichment fields: use `unknown` or omit the key. MUST NOT invent URLs or licenses.

Stills are optional identity aids. They MUST NOT replace WebSearch enrichment for `links`.

In entry bodies, show cover and gallery as a compact markdown image table under **What it is** for Cursor preview (`thumb-*.jpg` ~320px). The Hugo site strips that table and injects a GLightbox gallery grid from frontmatter `media` (see `site/layouts/_partials/library-gallery.html`).
